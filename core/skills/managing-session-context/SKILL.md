# 세션 컨텍스트 관리

원칙: **작업 경계에서 리셋하고, 작업 중에는 compact에 맡기고, 상태는 항상 디스크에 둔다.** 근거는 하네스 저장소의 `docs/context-policy.md`에 있다.

| 수단 | 언제 | 누가 |
| --- | --- | --- |
| 소프트 신호 | 사용량이 약 300k 토큰을 넘었을 때 | hook이 세션에 알림 |
| auto-compact | 작업 중 약 400k 토큰에 이르렀을 때 | 도구가 자동으로 |
| `/clear` | 커밋을 마친 뒤, 연관 없는 다른 작업으로 넘어갈 때 | Orchestrator가 판단·실행 |
| 예외 정리 | compact로 복구되지 않을 때 | 워커가 요청 |

사용량 비율은 판단 기준으로 쓰지 않는다. 같은 30%도 창 크기에 따라 토큰 양이 다르기 때문이다. 값은 `.agents/harness.env`에서 정한다.

## 작업 상태 파일

리셋이든 compact든 살아남는 것은 디스크뿐이다. 워커는 작업을 시작할 때 만들고, 결정이 생길 때 바로 고친다.

경로: `~/.claude/herdr/handoff/<프로젝트 이름>/<role>.md`(폴더가 없으면 만든다). 짧을수록 좋다. compact 뒤 맨 앞 40줄만 다시 주입된다.

```
작업: A-02 로그인 토큰 갱신 (worktree: docs/.worktrees/auth-refresh)
수용 기준: <배정 메시지 그대로>
결정: <왜 그렇게 했는지. 코드에서 알 수 없는 것만>
다음 행동: <바로 이어서 할 일 한 줄>
주의: <미커밋 파일, 건드리면 안 되는 곳>
```

코드와 git에서 알 수 있는 내용은 적지 않는다.

## 작업 중

- 사용량 때문에 작업을 끊지 않는다. 차면 compact가 처리한다.
- `[compact 복구]` 알림을 받으면 주입된 작업 상태와 스냅샷으로 위치를 확인하고, 수용 기준을 다시 읽은 뒤 이어 간다. 기억나지 않는 결정을 추측하지 말고 파일과 커밋에서 확인한다.
- 워커가 `[컨텍스트 소프트 신호]` 알림을 받으면 지금 작업을 수용 기준까지 계속한다. 차면 compact가 처리하므로 서두르거나 미완성 작업을 `[완료]`로 보고하지 않는다. 신호만으로 `/clear`를 요청하지 않는다. 다음 배정은 Orchestrator가 정한다.
- Orchestrator가 신호를 받으면 처리 중인 보고까지 마치고, 상태판과 세션 장부를 고친 뒤 `herdr-report "[CLEAR 요청] <이유>"`를 보낸다. 상태가 모두 디스크에 있으므로 언제든 이어 갈 수 있다.
  - 정리를 기다리는 동안에도 이미 계획한 같은 묶음의 배정, `[병합]` 지시, 보고 처리는 계속한다. 새 묶음의 계획과 연관 없는 큰 판단만 정리 뒤로 미룬다. 정리 대기 때문에 워커를 놀리지 않는다.
  - Commander가 없거나 `HERDR_CLEAR_TIMEOUT`(기본 30분) 동안 정리하지 않으면, 감시자(`herdr-watch`)가 Orchestrator가 쉴 때 대신 정리하고 `재개`를 보낸다(ohmystock 2026-11-11: Commander가 없어 정리 요청이 하루 동안 처리되지 않았고 그동안 새 배정이 멈췄다).
- Commander가 신호를 받으면 사용자에게 정리를 요청한다.
- Codex 세션은 맥락 크기를 기록하는 hook이 없다. 상태줄 `Context N% used`로 스스로 판단하고, Orchestrator는 `hc read <t> | grep -o 'Context [0-9]*% used'`로 확인한다. 이때만 비율을 창 크기에 곱해 토큰으로 환산한다.

## 작업 경계: 정리할지 정하기

어느 세션에 줄지는 `running-herdr-autopilot`의 `references/orchestrator.md`("세션 고르기")로 먼저 정한다. 이 표는 고른 세션을 정리한 뒤 줄지만 정한다. 판단 재료는 세션 장부의 맥락 칸이다.

| 고른 세션과 다음 작업의 관계 | 처리 |
| --- | --- |
| 같은 묶음이거나 연관 높음 | 그대로 배정. 맥락 크기와 compact 횟수는 보지 않는다 |
| 연관 없음 | 정리 후 배정 |

**처리 중인 작업은 끝까지 하고, 연관 없는 다른 작업은 `/clear` 뒤에 시작한다.** 이어 가는 작업의 맥락은 compact가 관리한다. 작업의 크기는 보지 않는다.

이 표는 워커 세션에 적용한다. Orchestrator와 Commander는 배정을 받지 않고 상태가 디스크에 있으므로 소프트 신호로 자기 정리를 요청한다. 아래 예외 정리는 그 이유로 따로 정한다. 독립 검증 서브에이전트는 매번 새 맥락으로 뜨고 끝나므로 정리할 것이 없다.

정리는 커밋이 끝난 깨끗한 상태에서만 한다. 작업 상태는 이미 git과 상태판에 있으므로 인계 문서를 따로 쓰지 않는다. 다음 `[배정]`이 곧 다음 세션의 시작이다.

## 정리 실행

`herdr-clear`로 실행한다. 대상이 쉬기를 기다려 `/clear`를 치고, 거부되지 않았는지 확인한 뒤 다음 메시지를 보낸다. `hc send`는 `<hc from>`으로 감싸 붙이므로 `/clear`를 그것으로 보내면 명령으로 듣지 않는다.

```bash
herdr-clear orchestrator                          # /clear 뒤 "재개"
herdr-clear --send "[배정] <내용>" worker-1        # /clear 뒤 다음 배정
```

직접 쳐야 하면 `hc wait <t>`, `hc keys <t> / c l e a r enter`, `hc wait <t>`, `hc send <t> "<다음 메시지>"` 순서다.

- Claude 세션에 `hc keys <t> esc esc`를 보내지 않는다. 되감기(Rewind) 창이 열려 잘못 고르면 대화가 되돌아간다. 입력창을 비우는 데에도 쓰지 않는다.

| 대상 | 실행하는 쪽 |
| --- | --- |
| 워커 | Orchestrator |
| Orchestrator | Commander(Orchestrator가 상태판·장부를 고친 뒤 `[CLEAR 요청]`을 보낸다). Commander가 없거나 처리하지 않으면 감시자 |
| Commander | 사용자에게 요청한다 |

- 대상이 쉬고 있고 맡은 작업이 끝났을 때만 실행한다. 작업 중이면 도구가 `/clear`를 거부하고 맥락이 그대로 남는다.
- 맡은 작업이 끝난 때는 종류마다 다르다. 병합하는 작업은 `[병합완료]`를 받은 뒤, 병합하지 않는 작업은 `[완료]`를 받아들인 뒤다. 첫 `[완료]`만으로는 정리하지 않는다. 예외 정리는 아래 절차를 따른다.
- 거부되면(`is disabled`) `herdr-clear`가 끝 코드 3으로 알린다. 끝나기를 기다렸다가 다시 실행한다.
- `/clear`는 터미널 라벨을 지우지 않으므로 역할은 유지된다. 정리 뒤 세션 장부의 맥락 칸을 비운다.

## 예외 정리: 작업 중 복구가 안 될 때

아래 경우에만 작업 도중 정리한다.

- compact가 연달아 실패하거나 compact 직후 다시 차서 자동 compact가 멈췄다.
- compact 뒤 같은 실수를 되풀이하거나 수용 기준·결정을 잃어 파일로도 복구되지 않는다.

```
예외 정리:
- [ ] 1. 작업 브랜치에 안전한 지점까지 커밋한다(미완성이면 커밋 메시지에 표시)
- [ ] 2. 작업 상태 파일의 다음 행동과 주의를 이어받을 수 있게 고친다
- [ ] 3. herdr-report로 보낸다: [CLEAR 요청] <이유>, <상태 파일 경로>
- [ ] 4. 멈춰 기다린다
```

Orchestrator는 상태 파일의 다음 행동이 구체적인지 확인하고 부족하면 보완을 지시한다. 충분하면 "정리 실행"을 하고 `재개`를 보낸다.

## "재개"를 받은 세션

역할을 확인하고, `running-herdr-autopilot` 스킬과 자기 역할 파일, 작업 상태 파일을 읽은 뒤 다음 행동부터 이어 간다. Orchestrator는 상태판과 세션 장부를 읽는다. 작업 상태 파일이 없으면 배정을 기다린다.

## 유입량 줄이기

리셋과 compact 빈도는 유입량으로 정해진다.

- 서로 독립인 읽기·검색·명령은 한 번에 묶어 보낸다.
- 파일은 필요한 범위만 읽고, 코드 위치 찾기는 심볼 인덱스(graft 등)가 있으면 먼저 쓴다.
- 검사 출력은 종료 상태와 실패 발췌만 받고, 긴 전문은 파일로 남긴다.
- 느린 명령은 자기 셸에서 기다리지 않고 `hc run --bg --rm --no-notify --name <이름> <명령>`으로 돌린 뒤 `hc wait <이름>`으로 받는다. 기다리는 동안에도 메시지를 받을 수 있다.
