# 단계 0 결과: 같은 일을 다시 겪는가

[적용 계획](proposal.md)의 단계 0을 jobtailor에서 한 번 해 본 결과다(2026-11-11).

**결론: 다음 단계로 넘어간다.** 두 세션 이상이 다시 겪은 것 가운데 새로 배운 것이 7개다. 넘어가는 조건(3개 이상)을 넘었다. 이미 문서에 있는데도 다시 겪은 것도 2개 있었다.

## 어떻게 쟀나

- 대상: jobtailor Claude 대화 기록 148개 중, 세션 시작 문구("이 세션의 역할은 worker-N")로 고른 워커 세션 15개 가운데 최근 10개(11/09~11/11). 지금 돌고 있는 세션 1개는 뺐다.
- 뽑은 부분: 받은 메시지, 오류 난 도구 결과와 그 앞뒤 호출, compact 요약, 마지막 글. 원본 약 50MB → 181KB(도구 오류 36건).
- 분석: 파일을 고칠 수 없는 세션이 후보를 적고, jobtailor의 `AGENTS.md`·스킬·`docs`와 맞춰 나눴다. 증거 문구 일부는 손으로 다시 확인했다.

## 다시 겪은 것 (두 세션 이상)

| 배운 것 | 세션 수 | 분류 |
| --- | --- | --- |
| Bash 도구는 `sleep N; 명령`을 막는다. 기다릴 때는 Monitor나 `run_in_background`를 쓴다 | 4 (6번) | 문서에 있음, 그래도 겪음 |
| rebase와 병합 사이에 Orchestrator가 main에 상태판을 커밋한다. `merge --ff-only` 직전에 다시 rebase한다. `&&` 사슬 안에서 `\| tail`로 넘기면 병합 실패가 가려진다 | 3 | 새것 |
| 짧은 작업도 한 번에 `cat` 여러 파일이 exit 1을 내 따로 다시 읽는다(원인 미확인) | 3 | 새것 |
| `herdr-report`를 `timeout`으로 감싸면 관문 검사 도중 죽어 보고가 안 간다 | 2 | 문서에 있음, 그래도 겪음 |
| ruff 줄 길이 100에서 한글이 두 칸으로 세어져 한글 docstring이 E501로 걸린다(한글 61자 줄을 116으로 셈, 2026-11-11 확인) | 2 | 새것 |
| 뒤에서 보낸 `herdr-report`는 다음 턴의 Stop hook 보고로 세지 않는다. 앞에서 다시 보낸다 | 2 | 새것 |
| 셸은 zsh다. 따옴표 없는 `--include=*.md`는 "no matches found", 공백 든 `$VAR`는 나뉘지 않는다 | 2 | 새것 |
| 임시 Python 스크립트: `-I`는 `PYTHONPATH`를 버리고, 표준 모듈 이름(`struct.py`)은 import를 깨뜨린다 | 2 | 새것 |
| `make mutate-changed`가 server에서 30~40분 넘게 돈다. 범위를 좁힌다 | 2 | 새것 |

새로 배운 것 가운데 한 세션에서만 나온 것은 5개다(macOS `sed -i ''`, `.manifest.json` 파일 이름, 임시 서버 API 토큰, `.tsx`에서 컴포넌트만 내보내기, 위험한 `rm` 확인창에 멈춤). 한 번만 쓸 것은 4개다.

## 함께 알게 된 것

- **배운 것 기록만으로는 모자란 것이 있다.** `sleep`과 `timeout herdr-report`는 이미 문서에 있는데도 다시 겪었다. 문서 문장이 상황(Bash 도구가 막음, 보고 명령을 감싸지 말 것)을 직접 말하지 않아서다. 이런 것은 기록을 쌓기보다 규칙 문장을 고치거나 hook으로 막는 편이 낫다.
- **하네스 자체의 문제도 섞여 있다.** 뒤에서 보낸 보고를 Stop hook이 세지 않는 것은 하네스(`worker-turn.sh`) 쪽 문제다. 하네스 저장소에서 고친다.
- **규칙 위반 1건**: 한 세션(da15ae82)이 `git -c core.hooksPath=/dev/null commit`으로 pre-commit 검사를 건너뛰었다. `implementing-with-tdd`가 금지하는 일이다.

## 바로 고친 것 (2026-11-11)

배운 것 기록(단계 1)보다 먼저, 다시 겪은 함정을 규칙 문장으로 막았다.

- 하네스 `core/skills/running-herdr-autopilot/references/worker.md`:
  - 기다릴 때 `sleep` 대신 알림이나 Monitor를 쓴다.
  - `herdr-report`를 `timeout`이나 백그라운드로 감싸지 않고, 오래 걸리면 `--bg`를 쓴다.
  - WIP 커밋이라도 커밋 검사를 건너뛰지 않는다.
  - 병합 출력을 `| tail`로 넘기지 않는다.
  - 빨리 감기 실패가 자주 나는 이유(Orchestrator의 상태판 커밋)를 적었다.
- jobtailor `AGENTS.md` 프로젝트 규칙에 ruff 한글 폭, zsh, 임시 Python 스크립트, 뮤테이션 시간, macOS sed를 묶은 "다시 겪은 함정" 한 줄을 더했다.
- 뒤에서 보낸 보고를 Stop hook이 세지 않는 문제는 hook을 고치지 않았다. 원인은 `herdr-report`를 Bash 도구의 백그라운드로 돌린 것이다. 하네스에는 이미 곧바로 돌아오는 `herdr-report --bg`가 있으므로 규칙 문장으로 막았다.
- 효과는 다음 측정(같은 방법으로 워커 세션 10개)에서 같은 함정이 줄었는지로 본다.

## 이 측정의 한계

- 오류 난 도구 호출만 봤다. 오류 없이 돌아간 재시도, 느린 우회, 틀린 접근은 빠졌다. 실제 손해는 이보다 크다.
- 이틀치, 워커 두 자리뿐이다. "다시 겪음"이 같은 자리의 이어진 세션일 수 있다.
- 문서 대조는 낱말 검색이라, 다른 말로 적힌 것을 놓쳤을 수 있다.
- 시간 손해(다시 돈 관문 검사, 40분 뮤테이션)는 재지 않았다.
- 추출 스크립트는 저장소에 넣지 않았다. 단계 2에서 다시 쓸 일이 생기면 그때 넣는다.
