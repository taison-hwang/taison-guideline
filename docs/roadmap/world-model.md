# 월드모델: 워커는 /clear만 쓰고 프로젝트 맥락은 월드모델에서 받는다

차기 버전 계획이다. 아직 만들지 않았다. 방향만 정했고, 방식은 아래 "정할 것"에서 정한다.

## 목표

- 워커 세션의 컨텍스트 관리는 `/clear` 하나로 한다. 작업 중 auto-compact에 기대지 않는다.
- 프로젝트의 형상, 상태, 진행 맥락을 "월드모델" 한 곳에 둔다.
- 워커는 `/clear` 뒤 새 작업을 시작할 때 월드모델에서 이 셋을 받아 실행한다.

## 지금 구조

지금 정책은 "작업 경계에서 리셋하고, 작업 중에는 compact에 맡기고, 상태는 항상 디스크에 둔다"이다(`managing-session-context` 스킬, [컨텍스트 정책의 근거](../policy/context-policy.md)).

| 수단 | 지금 |
| --- | --- |
| `/clear` | 커밋을 마친 뒤, 연관 없는 작업으로 넘어갈 때 Orchestrator가 실행한다 |
| auto-compact | 작업 중 약 400k 토큰에서 도구가 자동으로 한다. `[compact 복구]` hook이 작업 상태 파일 앞 40줄을 다시 넣는다 |
| 소프트 신호 | 약 300k 토큰에서 hook이 알린다 |
| 연관 작업 | 같은 묶음이거나 연관이 높으면 정리하지 않고 같은 세션에 이어서 준다 |

프로젝트 맥락은 여러 곳에 나뉘어 있다.

| 맥락 | 지금 있는 곳 |
| --- | --- |
| 형상(코드 구조, 규약) | 코드와 git, `AGENTS.md`, `intent.md`, 프로젝트 문서 |
| 상태 | 상태판, 작업 계획, 검사 기록(`checks.tsv`), 판정 기록(`verdicts.tsv`) |
| 진행 맥락 | 개발 과정 기록(`docs/progress/`), 작업 상태 파일(`<role>.md`), `[배정]` 원문, 세션의 대화 |

마지막 줄의 "세션의 대화"가 문제다. 연관 작업을 같은 세션에 이어 주는 것은 이 대화 속 맥락을 살리기 위해서다. 그런데 이 맥락은 compact를 거치면 모델이 쓴 요약으로 바뀌고, 세션이 끝나면 사라진다.

## 바꾸려는 것

| | 지금 | 차기 |
| --- | --- | --- |
| 워커의 컨텍스트 관리 | 작업 경계 `/clear` + 작업 중 compact | `/clear`만 |
| 워커가 맥락을 얻는 곳 | `[배정]`, 여러 상태 파일, 이전 대화 | 월드모델 + `[배정]` |
| 연관 작업 배정 | 맥락이 남은 세션에 이어 준다 | 어느 세션에 주든 월드모델에서 같은 맥락을 받는다 |
| compact 복구 | hook이 작업 상태를 다시 넣는다 | 워커에는 필요 없다 |

## 월드모델이 담을 것(초안)

| 칸 | 내용 |
| --- | --- |
| 형상 | 모듈과 그 관계, 지켜야 할 규약, 바꾸면 안 되는 곳 |
| 상태 | 작업 계획과 상태판, 병합된 것, 진행 중인 작업과 그 worktree, 최근 검사·판정 결과 |
| 진행 맥락 | 결정과 그 이유, 이전 작업에서 배운 것, 남은 일과 막힌 일 |

코드와 git에서 바로 알 수 있는 것은 담지 않는다. 지금 작업 상태 파일 규칙과 같다.

## 정할 것

- **형태:** 파일 묶음(예: `docs/world/`)으로 할지, 조회 명령이나 MCP 서버로 할지.
- **갱신:** 누가 언제 고치는가. Orchestrator, `[병합완료]` 때의 `herdr-report`, hook 가운데 어디서 고칠지. 낡은 내용을 어떻게 막을지.
- **넣기:** 워커가 시작할 때 전부 넣을지, 작업에 맞는 부분만 골라 넣을지. `session-start.sh` hook을 쓸지.
- **작업 크기:** compact 없이 한 작업이 컨텍스트 안에 끝나야 한다. 이를 넘는 작업을 Orchestrator가 어떻게 나눌지, 그래도 넘치면 어떻게 할지.
- **compact 끄기:** 도구별로 auto-compact를 끄거나 늦추는 방법(Claude, Codex).
- **적용 범위:** Orchestrator·Commander도 같은 방식으로 바꿀지, 워커만 바꿀지.
- **기존 장치 정리:** 소프트 신호, `[compact 복구]`, 작업 상태 파일, 세션 장부의 맥락 칸 가운데 무엇을 남길지.
- **세션 사이 기억과의 관계:** [Dreaming·지식 위키 검토](../dreaming/index.md)에서 본 장치를 월드모델의 진행 맥락 칸으로 쓸 수 있는지.

## 단계(초안)

1. 설계: 위 "정할 것"을 정해 이 문서를 고친다.
2. 최소판: 지금 있는 상태 파일을 모아 워커 시작 때 넣는 형태로 만든다.
3. 시험: 한 프로젝트에서 워커의 compact를 끄고 `/clear`만으로 돌린다.
4. 측정: `herdr-usage`(토큰)와 `herdr-flow`(대기·작업 시간)로 전후를 비교하고, 되풀이 오류(`herdr-usage --errors`)가 늘지 않는지 본다.
5. 도입: 결과가 좋으면 `managing-session-context` 스킬과 컨텍스트 정책 문서를 바꾸고 기본값으로 한다.
